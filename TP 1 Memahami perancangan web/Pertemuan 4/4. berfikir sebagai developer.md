# Berpikir Sebagai Developer: Mengubah Desain Figma Menjadi Container HTML

## Kompetensi Dasar

Setelah mempelajari materi ini, peserta didik mampu:
- Menjelaskan cara kerja *Box Model* pada HTML/CSS.
- Membaca tata letak desain di Figma dan membaginya ke dalam struktur kotak (*containers*).
- Menerjemahkan susunan visual Figma menjadi struktur kode HTML semantik secara terstruktur.
- Memahami kesamaan antara fitur **Auto Layout** di Figma dengan **Flexbox** di CSS.

---

# Pendahuluan

Ketika seorang desainer UI/UX memberikan Anda file desain Figma, Anda mungkin melihatnya sebagai gambar yang indah, penuh warna, dan ikon yang menarik. Namun, **seorang Web Developer harus melihat desain tersebut dengan cara yang berbeda.**

Developer tidak melihat halaman web sebagai gambar utuh, melainkan sebagai **tumpukan kotak-kotak (boxes)** yang saling bersarang (*nested*). Proses menerjemahkan desain visual menjadi kotak-kotak kode ini disebut dengan **Slicing Layout** atau **Structuring Containers**.

---

# 1. Konsep Dasar: Semuanya adalah Kotak (Box Model)

Dalam dunia pengembangan web, aturan pertamanya adalah: **Semua elemen di halaman HTML adalah kotak.**

Mulai dari teks terkecil, tombol bulat, hingga latar belakang halaman web, semuanya dibaca oleh browser sebagai kotak segi empat.

```text
+-------------------------------------------------------------+
|  Container Utama (Page Wrapper)                             |
|  +-------------------------------------------------------+  |
|  |  Header (Kotak 1)                                     |  |
|  +-------------------------------------------------------+  |
|  |  Content Area (Kotak 2)                               |  |
|  |  +------------------------+   +--------------------+  |  |
|  |  | Kolom Kiri (Kotak 2A)  |   | Kolom Kanan (2B)   |  |  |
|  |  +------------------------+   +--------------------+  |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
```

Jika desainer UI/UX menggabungkan elemen visual menggunakan **Frame** atau **Group** di Figma, maka bagi developer, itu adalah sinyal kuat bahwa area tersebut harus dibuat menggunakan tag kontainer seperti `<div>`, `<section>`, `<header>`, `<main>`, atau `<footer>`.

### Langkah 1: Tentukan Pembungkus Terluar (Global Container)
Tentukan apakah halaman web ini memiliki lebar penuh (*full-bleed*) atau dibatasi dalam sebuah kartu (*boxed container*).
- *Contoh di Figma*: Sebuah frame berukuran Mobile (*Android/iPhone*).
- *Di HTML*: Kita membuat `<div class="mobile-container">`.

### Langkah 2: Potong secara Vertikal (Top-to-Bottom)
Bagi halaman dari atas ke bawah menjadi beberapa blok utama yang sejajar.
- *Contoh*:
  1. Bagian atas: Foto profil dan nama (Header).
  2. Bagian tengah: Daftar tombol link (Main Content).
  3. Bagian bawah: Sosmed & Hak cipta (Footer).

### Langkah 3: Potong secara Horizontal (Left-to-Right)
Masuk ke dalam setiap blok utama, perhatikan apakah ada elemen yang berjejer secara mendatar (kiri ke kanan).
- *Contoh*: Ikon sosial media yang tersusun menyamping.
- *Di HTML*: Kita membutuhkan container baris (`display: flex; flex-direction: row;`).

### Langkah 4: Identifikasi Elemen Atom (Isi Terkecil)
Identifikasi teks, gambar, tombol, atau ikon di dalam container terkecil.
- *Contoh*: Gambar profil (`<img>`), nama (`<h1>`), paragraf bio (`<p>`), tombol (`<a>` atau `<button>`).

# 3. Studi Kasus Slicing: Halaman Link-in-Bio

Mari kita analisis struktur halaman `test.html` yang telah kita buat sebelumnya:

### A. Analisis Visual Figma ke Kotak HTML
Perhatikan bagaimana mata developer membedah desain visual menjadi kotak HTML:

```text
+---------------------------------------------------+
| .mobile-container                                 |
|                                                   |
|   +-------------------------------------------+   |
|   | .profile-section (Header)                 |   |
|   |   [ .profile-image-container (Gambar) ]   |   |
|   |   [ h1: Dandi HK ]                        |   |
|   |   [ p: Bio Kucing ]                       |   |
|   +-------------------------------------------+   |
|                                                   |
|   +-------------------------------------------+   |
|   | .links-container (Main Content)           |   |
|   |   [ a.link-button: itch.io ]              |   |
|   |   [ a.link-button: Shopee ]               |   |
|   |   [ a.link-button: Tokopedia ]            |   |
|   +-------------------------------------------+   |
|                                                   |
|   +-------------------------------------------+   |
|   | .social-icons-container (Footer)          |   |
|   |   [ a: Email ] [ a: IG ] [ a: FB ]        |   |
|   +-------------------------------------------+   |
|                                                   |
+---------------------------------------------------+
```

### B. Hasil Kode HTML-nya
Berdasarkan analisis kotak di atas, susunan HTML-nya menjadi sangat rapi dan logis:

```html
<!-- Container Utama Terluar -->
<div class="mobile-container">

    <!-- Bagian Profil (Kotak Vertikal) -->
    <header class="profile-section">
        <div class="profile-image-container">
            <img src="media/image.jpg" alt="Profil">
        </div>
        <h1 class="profile-name">Dandi HK</h1>
        <p class="profile-bio">Kucing berenang ikan berlari</p>
    </header>

    <!-- Bagian Tombol Tautan (Kotak Vertikal Berisi Tombol) -->
    <main class="links-container">
        <a href="#" class="link-button">itch.io</a>
        <a href="#" class="link-button">Shopee</a>
        <a href="#" class="link-button">Tokopedia</a>
    </main>

    <!-- Bagian Sosial Media (Kotak Horizontal) -->
    <footer class="social-icons-container">
        <a href="#" class="social-icon"><i class="fab fa-instagram"></i></a>
        <a href="#" class="social-icon"><i class="fab fa-facebook"></i></a>
    </footer>

</div>
```

# 4. Figma Auto Layout -> CSS Flexbox

Jika desainer menggunakan fitur **Auto Layout** di Figma, tugas developer menjadi jauh lebih mudah karena properti Auto Layout memetakan langsung ke **CSS Flexbox**.

Berikut adalah kamus terjemahan dari Auto Layout Figma ke CSS Flexbox:

| Properti di Figma | Pengaturan di Figma | CSS Code Equivalents |
| :--- | :--- | :--- |
| **Direction** | Panah Bawah (Vertical) | `display: flex; flex-direction: column;` |
| **Direction** | Panah Kanan (Horizontal) | `display: flex; flex-direction: row;` |
| **Gap (Spacing)** | Nilai angka (misal: `16px`) | `gap: 16px;` |
| **Padding** | Angka padding dalam (misal: `24px`) | `padding: 24px;` |
| **Alignment** | Rata Tengah (*Center*) | `justify-content: center; align-items: center;` |

---

# 5. Tips Developer: Trik "Border Merah" 

Ketika Anda kesulitan melihat pembagian container saat menulis kode CSS, gunakan trik rahasia developer ini di file CSS Anda:

```css
* {
    border: 1px solid red !important;
}
```

Trik ini akan memberikan garis tepi merah tipis pada **setiap kotak** yang ada di halaman web Anda. Dengan begitu, Anda bisa melihat dengan jelas:
- Di mana batas akhir sebuah container.
- Apakah ada container yang meluap (*overflow*).
- Apakah jarak antar kotak (*gap/margin*) sudah sesuai dengan desain di Figma.

---

# Rangkuman

1. **Kotak di dalam Kotak**: Jangan terburu-buru menulis kode teks atau tombol. Buatlah dahulu container luar yang membungkusnya.
2. **Gunakan Elemen Semantik**: Gunakan tag seperti `<header>`, `<main>`, `<nav>`, dan `<footer>` alih-alih menggunakan `<div>` untuk semua kotak agar website mudah dibaca oleh mesin pencari (SEO) dan ramah pembaca layar (Aksesibilitas).
3. **Pahami Figma Auto Layout**: Jika desain Figma rapi menggunakan Auto Layout, struktur Flexbox Anda akan menjadi jauh lebih mudah dirancang.
